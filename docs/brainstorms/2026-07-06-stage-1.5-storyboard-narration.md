## 1. Vấn đề (problem-first)

**Triệu chứng người dùng nêu:** "Đã có mô tả/thoại/ghi chú nhưng chưa biết đặt hay thay phần nào cho giọng đọc. Và các ảnh không liên kết nội dung, hơi khó hiểu."

**Decompress → vấn đề gốc (1 gốc, 2 biểu hiện):**
> Manifest Stage 1 là *bảng trích xuất theo trang*, nhưng Stage 2 (video) cần một *kịch bản đọc tuyến tính gắn với từng nhịp hình ảnh*. Thứ đó chưa tồn tại.

- 3 field `description/dialogue/note` là **nguyên liệu thô**, không phải kịch bản. Prompt vision cố ý "chỉ mô tả, không viết lời bình sẵn". → thiếu khái niệm `narration` (lời đọc cuối) ⇒ "không biết đặt/thay phần nào".
- Đơn vị đang là **cả trang** = 1 cục mô tả + mảng thoại phẳng ⇒ không biết "khi ảnh/vùng nào lên hình thì đọc câu nào" ⇒ "ảnh không liên kết nội dung".

**Evidence status:** Strong (đọc trực tiếp `lib/schema.ts`, `lib/vision.ts`, `app/page.tsx`; contract dừng ở mức bảng, không có timeline/script).

## 3. Thiết kế đồng thuận

### 3.1 Khái niệm mới — Beat (nhịp) = hợp đồng cho Stage 2

```ts
interface Beat {
  id: string;
  order: number;
  sourceIndex: number;              // trỏ về trang gốc trong manifest Stage 1
  region: { x: number; y: number; w: number; h: number } | null; // null = cả trang; band = dải y
  narration: string;                // LỜI ĐỌC cuối (mô tả+thoại đã ghép, sửa tay được)
  sourceDialogue?: string[];        // thoại gốc — truy vết khi sửa
  durationHint?: number;            // ước lượng giây theo độ dài text — canh timing
}

interface StoryboardManifest {
  version: number;
  jobId: string;
  createdAt: string;
  beats: Beat[];
  voice?: { /* cấu hình giọng cho Stage 2 */ };
}
```

- `narration` giải quyết "đọc phần nào" — **một** dòng text rõ ràng.
- `region` trên `sourceIndex` giải quyết "hình↔lời" — ràng buộc chính xác + đích pan/zoom.

### 3.2 Luồng Stage 1.5

1. **Nạp:** manifest Stage 1 + ảnh gốc (cùng session; hoặc upload lại + manifest JSON). **PDF → render trang ra raster trước** (ingest mới).
2. **Đề xuất nhịp (region cuts):** heuristic **gutter-detection** (dải ngang variance thấp qua `sharp` raw pixels).
   - Webtoon/PDF dải dọc → cắt band theo gutter.
   - Manga trang → mặc định cả trang = 1 nhịp (fallback).
3. **Gán nội dung↔band (hybrid theo nguồn):**
   - **2A (webtoon/PDF dài):** crop từng band → chạy vision **trên ảnh band** → narration riêng. Toạ độ tin 0%, sync chuẩn. Cost +1 lượt vision/band.
   - **2B (manga trang):** dùng lại content Stage 1 → LLM chia nhịp theo thứ tự → zip nhịp↔band. Rẻ, tái dùng dữ liệu.
4. **Ghép narration:** LLM soạn lời kể recap 1 giọng (tiếng Việt), thoại lồng dạng trích.
5. **Sửa tay:** chỉnh text + kéo/chỉnh vùng crop trong UI.
6. **Export `StoryboardManifest`** → Stage 2 (TTS + Ken Burns render).

### 3.3 Ranh giới model vs heuristic (chốt cứng)

- **Heuristic lo PIXEL** (cắt band gutter). **Model lo NGHĨA** (tả band ở 2A / chia nhịp ở 2B).
- Model **KHÔNG vẽ bbox** — toạ độ pixel trên ảnh cao của GLM/4o không đáng tin.
- Model coarse-anchor (vị trí % thô) chỉ dùng khi gutter mờ, để **snap về gutter gần nhất** — phụ trợ.

## 4. Các phương án đã cân nhắc (và vì sao loại)

| Chủ đề | Phương án loại | Lý do |
|---|---|---|
| Độ chi tiết | Cả trang = 1 nhịp | Vỡ với webtoon/PDF dải dọc (ảnh cao ~12000px) |
| Độ chi tiết | Tách panel thật (cắt ảnh) | Panel detection đắt/khó; over-engineer cho tool 1 người |
| Tạo vùng | Model tự xuất bbox | Toạ độ pixel model không đáng tin trên ảnh cao |
| Chỗ tạo script | Mở rộng Stage 1 (thêm field narration) | Trộn "trích xuất trung thực" và "biên kịch" → khó sửa độc lập |
| Chỗ tạo script | Soạn tay khâu dựng | Thủ công, không tái lập được |
| Ghép narration | Template nối chuỗi | Văn cứng, phải biên tập nhiều |
